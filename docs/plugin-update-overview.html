Update strategy / decision overview

One product.
Two update lanes.

Keep Electron responsible for the installed application. Let the plugin platform deliver compatible features independently. The result: fewer heavyweight downloads, live plugin activation, and one dependable recovery path.

Decision matrix

The rule at a glance

Repository ownership makes the normal route explicit. Host and protected-core changes live in Termco; compatible feature plugins live in the plugin repository. Any dependency or contract expansion still requires a new application baseline.

Delivery flows

Different payloads, one update surface

Users see one Software Updates experience. Behind it, each lane keeps the responsibility it already understands.

Full application

Restart required
  1. Classify host changesCI detects trusted runtime or protected-core changes.
  2. Build application targetsElectron Builder creates platform installers and metadata.
  3. Sign and notarizeProduction artifacts carry the platform trust chain.
  4. Publish application releaseThe application repository remains the normal update feed.
  5. Install with electron-updaterDownload, verify, replace the installed app, then restart.

Plugin-only release

Live activation
  1. Build the complete snapshotThe current selected plugin set stays together from signing through activation.
  2. Package sourceThe application compiles every plugin into staging before the live transaction begins.
  3. Sign release metadataEd25519 protects plugin identity, compatibility, archive digest and revocations.
  4. Provision or offerFirst launch provisions automatically; later compatible releases present Update or Later.
  5. Stage and verifyCheck host compatibility, target, paths, hashes and complete graph.
  6. Activate transactionallyUse the proven main/renderer live-replacement transaction.
  7. Persist or roll backKeep the previous verified generation ready for recovery.

Safety model

Fast does not mean fragile

Downloaded plugin source and compiled generations persist locally. Seven bundled core plugins own setup, updates, management, diagnostics, and recovery even before the feature snapshot is provisioned.

01 User customizations win

Custom sources are never overwritten; a conflicting official set is blocked and explained.

02 Bundled recovery remains

The seven protected core plugins remain in the application; downloaded source is committed only after the whole set compiles.

03 Failures roll back

Activation or persistence failures and signed revocations can restore the last verified set.

04 Application updates win

If both lanes have an offer, install the new host baseline before considering plugins.
