01

Repository B

Confirm the plugin release repository

This repository owns official plugin source and its release artifacts, not Electron.

  1. Use the existing public repository termco-ai/termco-plugin-releases.
  2. Make it public unless plugin distribution must be private.
  3. Keep ordinary official plugins under plugins/ and the selected set in profiles/default/profile.json.
  4. Keep protected core plugins and application contracts pinned by the Termco host release.
  5. Use GitHub Releases in the same repository for the signed manifest and complete ZIP snapshot.
Public is the simpler production choice.

A private feed would require every installed application to authenticate. Do not embed a personal token in the application.

02

Trust root

Generate the Ed25519 signing key

Generate it locally. The private half signs releases; the application contains only the public half.

Terminal · run outside the repository if preferred
openssl genpkey -algorithm ED25519 -out plugin-release-private.pem
chmod 600 plugin-release-private.pem
openssl pkey -in plugin-release-private.pem -pubout -out plugin-release-public.pem
Never commit plugin-release-private.pem.

The repository already ignores *.pem, but the durable copy should live in a password manager or dedicated secret store.

06

            

              

                

                  
One-time bootstrap

                  
Ship one full application update

                  
Existing installations cannot trust the new feed until they receive its repository and public key.

                

                
              

              
    
                
  1. Commit the enabled plugin-release.json and first-launch bootstrap to the main source repository.
    2. 
                
  2. Build, sign, and publish the application using the existing Electron release process.
    3. 
                
  3. Install that application version on a clean machine or clean user profile.
    4. 
                
  4. Confirm the setup screen downloads, verifies, compiles, and activates the official plugin set.
    5. 
              

              

                This bootstrap cannot be a plugin-only release.
                
The public key and release manager are part of the trusted application baseline, so enabling them requires one normal application update.

    3.

Release asset 1termco-plugin-release.json

                
Release asset 2plugins-<release-id>.zip
